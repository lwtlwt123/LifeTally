# 日子有数 LifeTally 文档索引

产品英文名：LifeTally。它表达“把每天的生活记录、金额和提醒都盘清楚”，比纯记账类名字更适合这个综合生活管家。

这套文档以“移动端产品 + 自有 Node 服务 + 独立后台管理系统”为边界。先完成个人自用 MVP，同时保留多用户、家庭共享和上架后的扩展空间。

## 阅读顺序

1. [产品设计说明](日子有数-产品设计说明.md)：功能范围、业务规则、版本规划。
2. [接口设计](日子有数-接口设计.md)：移动端与服务端的接口、鉴权、状态和错误约定。
3. [OpenAPI 契约](openapi.yaml)：可导入 Swagger UI、Apifox、Postman 的 MVP 接口子集。
4. [后台管理系统设计](日子有数-后台管理系统设计.md)：管理端页面、角色、任务、审计与部署边界。
5. [AI 省钱分析设计](日子有数-LifeTally-AI省钱分析设计.md)：不必要支出识别、可节省金额估算、建议采用与提醒生成。

## 推荐技术落地

| 层 | 首选 | 说明 |
| --- | --- | --- |
| 用户端 | Vue 3 + TypeScript + Capacitor | H5、Android、iOS 共用业务代码。 |
| 用户 API | Node.js + TypeScript + Fastify | 轻量、类型友好，适合 REST 与文件签名上传。 |
| 后台管理端 | Vue 3 + TypeScript | 独立部署在 admin 子域，不与用户端混用登录态。 |
| 数据库 | PostgreSQL | 账务、读数、提醒、审计需要可靠事务。 |
| 队列与缓存 | Redis + BullMQ | OCR、GPT、通知、导出都走异步任务。 |
| 图片 | S3 兼容对象存储 | 私有桶，浏览与下载使用短期签名 URL。 |

## 关键约束

- 金额一律以 amountFen 整数传输和存储，前端仅负责格式化为元。
- 表计读数与用量使用十进制字符串，避免 JavaScript 浮点误差。
- OCR、GPT 和导入账单只产出候选数据；确认动作才会写入正式账本。
- AI 省钱分析只生成建议；采用后才创建预算规则、提醒规则或省钱目标。
- 用户端、后台端、任务执行器使用不同的访问令牌和权限模型。
- 后台默认不可查看原始票据、物品照片和精确住址；需要临时授权并留下审计记录。
