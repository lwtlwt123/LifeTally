# 日子有数 LifeTally：AI 省钱分析设计

版本：0.1

## 1. 功能定位

AI 省钱分析不是聊天助手，也不是自动管钱。它的职责是把已确认消费、预算、固定账单、通勤和能源数据整理成“可采用的建议卡”，告诉用户：

- 哪些支出可能没必要。
- 如果减少或取消，大概能省多少钱。
- 采用后会创建什么规则、提醒或目标。

所有建议都必须可拒绝、可稍后、可关闭同类提醒。

## 2. 建议类型

| 类型 | 说明 | 例子 |
| --- | --- | --- |
| unnecessary_spending | 高频小额或可控消费 | 奶茶、零食、打车、外卖、冲动购物。 |
| recurring_bill | 固定账单和订阅 | 会员、宽带、手机费、保修、重复服务。 |
| budget_risk | 预算风险 | 餐饮已用 80%，按当前速度月底超 ¥240。 |
| energy_cost | 家庭能源费用 | 电费高于近 7 天均值，建议检查电器使用。 |
| commute_cost | 通勤成本 | 打车或充电成本异常，建议切换路线或提前充电。 |
| reminder_timing | 提醒时间优化 | 总是延后上传电表，建议提前提醒。 |

## 3. 省钱估算规则

AI 不直接计算正式金额。Worker 先用规则生成数值，再把摘要交给模型解释。

~~~text
单次平均金额 = 分类候选支出金额 / 候选次数
预计月省 = 可减少次数 x 单次平均金额
预计年省 = 预计月省 x 12
分类超支 = 本月分类支出 - 历史月均分类支出
订阅年省 = 每月订阅金额 x 12
预算风险 = 按当前日均支出预测月末支出 - 月预算
~~~

候选支出要排除房租、水电、刚性账单、已报销、收入、转账和用户标记为“必要”的分类。

## 4. UI 建议卡

每张卡固定展示：

- 标题：一句话说明建议。
- 金额：预计月省和预计年省。
- 依据：次数、金额、历史对比或固定账单。
- 置信度：低于 0.65 的建议不主动打扰，只放在分析页。
- 动作：采用、不需要、稍后提醒。

示例：

~~~text
奶茶频率可以降一点
本月 9 次共 ¥162，降到每周 1 次。
预计月省 ¥90，全年约 ¥1,080
[采用目标] [不需要]
~~~

采用后可创建：

- saving_goal：例如“奶茶每月不超过 ¥72”。
- budget_rule：例如“餐饮本月剩余 ¥480”。
- reminder_rule：例如“工作日下午 15:00 前提醒少买奶茶”。
- checklist_rule：例如“雨天出门自动加入雨衣”。

## 5. 接口与任务

用户端接口：

- GET /api/v1/ai/spending-insights
- POST /api/v1/ai/spending-insights/generate
- POST /api/v1/ai/suggestions/{suggestionId}/actions

异步任务：

~~~text
transaction.confirmed
  -> update spending aggregates
  -> enqueue ai_analysis when threshold met
  -> create ai_suggestions
  -> user adopts suggestion
  -> create saving_goal / budget_rule / reminder_rule
~~~

后台只看聚合指标、失败率和采用率，不查看个人完整账单。

## 6. 隐私与文案边界

- 不发送完整票据、原图、精确地址和完整支付流水给模型。
- 发送给模型的是摘要：分类、次数、金额区间、趋势、候选建议。
- 文案不使用“浪费”“自控力差”等羞辱表达。
- 不自动创建提醒，不自动改预算，不自动删除账单。
- 用户拒绝后同类建议降频；用户关闭后不再生成同类建议。

## 7. MVP 验收

- 能识别至少 3 类可控消费：奶茶/饮料、外卖、打车。
- 能识别至少 1 类固定账单优化：订阅或会员。
- 每条建议都显示预计月省、预计年省和依据。
- 采用建议后能创建省钱目标或提醒规则。
- 低置信度建议不进入首页，只在 AI 分析页展示。
- 所有建议状态可追踪：new、adopted、dismissed、expired。
