# 日子有数 LifeTally：产品设计说明

版本：0.2

## 1. 产品定位

“日子有数 LifeTally”是面向个人和小家庭的生活数据管家。它将每天的电表照片、充电记录、消费票据、通勤信息、天气和家庭物品位置，转为可靠的金额计算、AI 省钱建议、提醒和可回看数据。

产品主线不是“多功能工具箱”，而是：

```text
生活事件 -> 结构化记录 -> 程序计算金额/状态 -> 提醒与月度分析
```

GPT 和 OCR 只负责读图、提取文字、消费分类和生成解释；金额、读数差、预算和续航判断必须由后端规则计算。

## 2. 首版目标

1. 看清今天、本月和预计的生活支出。
2. 用拍照和确认完成电表读数与消费记账，尽量少填表。
3. 根据电车续航、上下班距离和天气，在恰当时间提醒充电、带物品和出门。
4. 快速找回“家里的东西放在哪里”。
5. 分析不必要支出、异常增长和可取消固定账单，估算“如果省掉能省多少钱”。
6. 一套 Vue + TypeScript 前端同时发布 H5、Android 和 iOS；所有数据通过自有服务器同步。

## 3. 信息架构

### 首页：今日

- 今日支出、本月支出、预算剩余、待缴金额。
- 电车剩余续航、是否需充电、下一次出发需要的续航。
- 上下班时段天气和路线预计时间。
- 今日待上传电表、待带物品和固定账单提醒。

### 钱

- 收入、支出、转账、报销、固定账单。
- 消费记录：手动录入、收据 OCR、微信/支付宝账单截图或导出账单导入。
- 分类、支付方式、标签、预算、月度对比和导出。
- 电费、水费、燃气费、充电费自动进入对应分类。

### 通勤

- 电车档案、续航与充电状态。
- 上班/下班时间、家与公司地址、常用路线和实际通勤记录。
- 天气、拥堵、预计到达时间、雨具和随身物品提醒。

### 生活

- 电表、水表、燃气表：上传图片、确认读数、费用趋势。
- 家庭物品：物品、照片、位置、别名、最后确认时间。
- 固定服务：房租、物业、宽带、手机费、订阅、保修与到期提醒。

### 我的

- 账户与家庭成员、通知时间、预算、价格规则。
- 数据导出、原图管理、数据删除、隐私与第三方服务说明。

## 4. 核心业务规则

### 4.1 电表、水表、燃气表

1. 用户按周期上传表计图片。
2. OCR 返回候选读数、原图和置信度；用户必须确认或修改读数。
3. 后端只以“已确认读数”生成用量和金额。

```text
本期用量 = 本期确认读数 - 上期确认读数
本期费用 = 价格规则(本期用量, 周期, 峰谷读数)
```

电价规则需要支持固定单价、阶梯电价和峰谷电价。若只上传总表读数，不能准确拆分峰谷费用，应提示用户按总价或固定单价估算。

异常条件：读数小于上期、用量为负、单位用量超过近 7 天均值的可配置倍数、OCR 置信度过低。

### 4.2 电车续航与充电

每辆电车需记录：满电续航、可选电池容量（kWh）、默认电价、充电时长、当前预计续航、上次充电时间和电量/续航。

```text
下一次用车需求 = 去程距离 + 回程距离(可选) + 安全预留
需要充电 = 当前预计续航 < 下一次用车需求

本次充电费用 = 充电电量(kWh) x 电价(元/kWh)
预计通勤费用 = 实际里程 x 历史每公里成本
```

只记录“30 km 满电续航”和骑行里程时，费用只能估算。要精确计算，应记录充电电量、充电金额，或电池容量与充电百分比。系统需将“估算金额”和“实际金额”明确区分。

状态：未充电、建议充电、充电中、已充满、已跳过。充电完成后，用新的续航或电量更新当前状态。

### 4.3 消费和账本

每笔交易至少包含：金额、方向（收入/支出）、时间、分类、来源、确认状态。可选字段：商家、支付方式、图片、标签、拆分项、备注。

来源包括：手动输入、收据图片、微信/支付宝截图、账单导入、表计自动计算、充电记录和固定账单。所有 OCR 结果先进入“待确认”，确认后才进入统计。

注意：App 不应承诺自动读取用户微信或支付宝的全部个人消费记录。首版采用截图、收据、导出账单和手动录入。

### 4.4 预算与预测

```text
本月支出 = 已确认支出之和
预算剩余 = 月度预算 - 本月支出
预计月末支出 = 已确认支出 + 日均可变支出 x 剩余天数 + 待发生固定账单
```

预算可按总预算和分类预算设置。固定账单按到期日预留。首页仅展示用户最需要处理的金额、异常与待缴项目，不把全部图表堆在首页。

### 4.5 通勤、天气与路线

用户设置家、公司、上班时间、下班时间、常用路线和电车类型。系统在出发前查询天气与路线信息，生成提醒：是否下雨、预计耗时、是否需要提前出门、是否要带雨衣。

地图数据可用于路线、距离、拥堵和预计时间。红绿灯实时相位不作为决策依据；可记录红绿灯数量和用户手动标记的常堵路口，并通过实际通勤历史得出个性化建议。

### 4.6 出门/回家清单

清单分为“上班出门”“下班回家”“自定义场景”。每项可设置：工作日、天气为雨、特定时间、特定地点、一次性或长期重复。

触发后提供“已带上、今天不需要、稍后提醒”。不要强迫用户逐项打勾，避免提醒变成负担。

### 4.7 家庭物品位置

物品记录字段：名称、别名、类别、房间、容器/抽屉、照片、描述、最后确认时间。搜索“螺丝刀”“钥匙”“证件”时，应直接返回准确位置和照片。

### 4.8 AI 省钱分析与提醒建议

AI 不直接替用户创建提醒、修改预算或删除账单，而是生成“建议卡”。建议卡必须包含：建议标题、触发原因、预计可节省金额、影响范围、可信度、可采用动作和拒绝原因。

可分析的数据范围：

- 已确认交易、预算、固定账单和待确认消费。
- 已确认表计读数、用量异常、价格规则和上传习惯。
- 电车续航、充电记录、次日通勤距离和天气。
- 出门/回家清单完成情况、物品搜索频次和用户跳过记录。

省钱分析类型：

- 非必要高频支出：例如奶茶、零食、打车、外卖、冲动购物等高频小额消费。
- 异常增长分类：本月某分类显著高于近 3 个月均值。
- 固定账单优化：订阅、宽带、手机费、会员、保修到期和重复服务。
- 替代方案估算：例如每周少点 2 次外卖、早餐固定预算、减少打车次数。
- 能源与通勤成本：电费、充电费、每公里成本和路线成本变化。

节省金额必须由规则计算，AI 只负责解释和组织建议：

```text
预计月省 = 可减少次数 x 单次平均金额
预计年省 = 预计月省 x 12
分类超支 = 本月分类支出 - 历史月均分类支出
可控支出 = 排除固定账单、房租、水电等必要支出后的候选支出
```

示例建议：

- “本月奶茶 9 次共 ¥162，如果降到每周 1 次，预计本月可省 ¥90，全年约 ¥1,080。”
- “外卖晚餐比上月多 ¥186，如果工作日改成 2 次内，预计每月可省 ¥120。”
- “你有 2 个订阅连续 30 天未打开，合计 ¥38/月，取消后每年可省 ¥456。”
- “你连续 3 天在 20:30 后才上传电表，建议把电表提醒提前到 19:45。”
- “明天上班往返需要 18 km，你当前续航 12 km，建议今晚 22:00 前提醒充电。”
- “雨天你常搜索雨衣位置，建议雨天出门提醒自动加入雨衣。”
- “宽带费还有 3 天到期，建议提前一天提醒确认是否已缴。”

安全边界：

1. AI 只读已授权、已脱敏的摘要数据，不读取完整原图、精确地址和完整票据内容。
2. 金额、读数、续航和到期日仍由后端规则计算，AI 只能解释和组合提醒策略。
3. 用户点击“采用”后，服务端才创建或修改 reminder_rule、budget_rule 或 saving_goal；点击“不需要”会记录 dismissReason，用于降低同类建议频率。
4. 同一类 AI 建议 24 小时内最多出现一次，避免提醒泛滥。
5. 文案避免羞辱和焦虑表达，只说事实、金额和可选动作，例如“可省”而不是“浪费”。

## 5. 每日自动流程

```text
前一晚：检查次日通勤距离与当前续航 -> 需要时提醒充电
上班前：天气 + 路况 + 出门清单 -> 提醒出发与携带物品
到公司后：记录实际到达时间、路线和里程（可选）
下班前：回家天气 + 回家清单 + 电车续航 -> 提醒
晚间：提醒上传电表/确认消费截图；更新今日与本月金额
低频：AI 汇总消费、习惯和异常 -> 生成可采用的省钱与提醒建议
```

移动 App 使用本地通知作为基础提醒；服务器只负责需要天气、账单到期或多端同步的提醒。H5 可使用浏览器通知，但可靠性不应等同于 App。

## 6. 数据模型（首版）

| 模型 | 关键字段 |
| --- | --- |
| 用户 | id、昵称、时区、通知设置、月度预算 |
| 交易 | 金额、方向、分类、日期、来源、支付方式、图片、确认状态 |
| 表计读数 | 类型、读数、日期、原图、OCR 结果、确认人、价格规则版本 |
| 电车 | 名称、满电续航、电池容量、电价、当前续航、状态 |
| 充电记录 | 开始/结束时间、充电量、金额、充电前后续航、状态 |
| 通勤记录 | 日期、方向、路线、距离、预计/实际时长、天气、拥堵备注 |
| 提醒 | 类型、触发条件、时间、是否完成、稍后提醒时间 |
| AI建议 | 建议类型、原因摘要、预计节省金额、建议规则、可信度、状态、采用/拒绝记录 |
| 物品 | 名称、别名、位置、照片、类别、备注、最后确认时间 |
| 固定账单 | 名称、金额、周期、到期日、分类、是否已缴 |

## 7. 技术方案

```text
Vue 3 + TypeScript + Vite
        |
        +-- 浏览器 H5 / PWA
        +-- Capacitor -> Android APK / iOS App
        |
自有 API 服务
        +-- 用户与同步
        +-- 规则计算与通知任务
        +-- OCR 服务（RapidOCR 或 PaddleOCR）
        +-- GPT 调用代理与 AI 提醒建议
        +-- 天气和地图服务代理
        +-- 数据库与图片存储
```

前端不保存 GPT、OCR、地图、天气等密钥。所有第三方请求通过后端代理，后端做鉴权、速率控制、审计和数据脱敏。

原始表计和票据图片应以私有对象存储保存；记录访问权限、可配置保留期限，并支持用户导出和删除。

## 8. 权限与隐私

- 相机/相册：仅在拍表计、票据或物品图片时申请。
- 通知：用于充电、账单、出门与电表提醒。
- 定位：默认只在用户主动查看路线或设置通勤地点时使用；首版避免持续后台定位。
- AI 分析：默认只发送摘要字段，例如连续跳过次数、预算比例、距离缺口和提醒完成率，不发送完整票据、原图或精确地址。
- 数据分类：消费金额、票据图片、家庭物品位置、路线和时间都要在隐私政策中说明用途、保存期限与删除方式。
- 第三方：天气、地图、OCR、GPT 的数据流向要单独列明；优先只传完成服务所需的最少字段。

## 9. 版本规划

### MVP

1. 首页金额总览、支出/收入/预算和固定账单。
2. 电表拍照、OCR、确认读数、电费计算。
3. 电车续航、充电状态、通勤成本与充电提醒。
4. 上下班天气、出门/回家清单、本地通知。
5. 家庭物品位置搜索。
6. AI 提醒建议卡：只生成建议，用户采用后才创建提醒。

### 第二阶段

1. 水表和燃气表。
2. 收据/截图 OCR、账单导入、消费自动分类。
3. 路线历史、拥堵分析、通勤报表。
4. 家庭共享、家庭成员权限与协作清单。
5. GPT 月度报告、异常解释和自然语言查询。

### 第三阶段

1. 多账户资产、报销与导出模板。
2. 订阅识别、保修/耗材生命周期提醒。
3. 发布到 Android 应用商店和 App Store。

## 10. UI 原则

- 首页先给出金额和下一步行动，而非信息瀑布。
- 所有 OCR 结果必须显式区分“待确认”和“已入账”。
- 正常状态少用警告色；需要充电、超预算、读数异常才突出显示。
- 一次提醒只提供一个清楚的动作，例如“去充电”“确认读数”“带上雨衣”。
- AI 建议必须显示理由和采用按钮，不允许悄悄修改用户提醒。
- 金额、读数和状态使用稳定位置与等宽数字，防止内容变化导致界面跳动。
- 视觉基调：白色与暖灰背景，墨绿作为主要行动色，橙红用于提醒，青绿用于通勤/天气信息。
