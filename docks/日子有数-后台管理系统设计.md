# 日子有数 LifeTally：后台管理系统设计

版本：0.2  
定位：服务运维、数据安全和任务处理后台，不是给用户记账的第二套网页。

## 1. 为什么需要后台

即使当前只自己使用，后台仍有实际价值：

1. 看 OCR、导出、通知、天气和地图请求是否失败。
2. 处理用户主动发起的数据导出和删除。
3. 管理第三方服务可用性、额度、开关和重试。
4. 未来开放给朋友或上架后，不需要临时进数据库改数据。

后台不做的事：

- 不默认浏览用户付款截图、票据、物品照片、精确住址和路线。
- 不直接修改已确认交易金额或表计读数；纠错应走受控的业务操作并留下原因。
- 不保存 GPT、地图、OCR、推送服务的原始密钥明文。

## 2. 部署与系统边界

~~~text
app.example.com       用户 H5 / PWA
api.example.com       用户 API
admin.example.com     后台管理端
admin-api.example.com 管理 API，可与 api 复用进程但必须分路由和鉴权

PostgreSQL            业务、后台账户、审计日志
Redis + BullMQ        OCR、通知、导出、第三方调用队列
对象存储私有桶        原始图片与导出文件
~~~

后台必须使用独立 Cookie 域、独立 JWT audience 和独立权限中间件。不能拿用户 App 的 access token 调用 admin API。

## 3. 角色与权限

| 角色 | 用途 | 可做 | 不可做 |
| --- | --- | --- | --- |
| system_owner | 系统所有者，仅限自己 | 管理员、密钥引用、功能开关、删除申请审批、紧急访问审批 | 无 |
| ops_admin | 日常运维 | 重试任务、查看指标、关闭故障功能、处理通知失败 | 管理其他管理员、查看原图 |
| support_auditor | 支持与审计 | 查看脱敏用户信息、审计记录、删除进度 | 修改业务数据、查看精确隐私数据 |
| data_processor | 异常 OCR 协助 | 只处理用户授权后的单个 OCR 候选 | 查看无授权原图、导出数据 |
| read_only | 观察 | 查看健康指标和已聚合数据 | 一切写操作 |

权限按资源和动作拆分，例如 users.read_masked、jobs.retry、privacy.grant_sensitive_access、integrations.update。页面隐藏不等于权限控制，API 每个操作都要鉴权。

## 4. 信息架构

左侧导航固定为以下 9 组，避免做成一堆数据卡：

| 分组 | 页面 | 核心内容与主要操作 |
| --- | --- | --- |
| 总览 | 运行概览 | 今日活跃、失败任务、等待确认、通知成功率、对象存储容量；可跳至异常列表。 |
| 用户与家庭 | 用户、家庭、设备 | 脱敏手机号/邮箱、状态、最后活跃、设备；冻结会话、发起数据导出。 |
| 任务中心 | 任务队列、失败任务、死信队列 | OCR、GPT、通知、导入、导出任务；查看输入摘要、错误、重试、取消。 |
| 数据请求 | 导出、删除、敏感访问审批 | 数据生命周期、审批步骤、执行进度、到期清理。 |
| 通知 | 发送记录、提醒策略 | Push、本地提醒同步、失败原因、限流、重发。 |
| AI建议 | 省钱建议、提醒优化建议 | 建议生成量、采用率、忽略原因、模型错误；只展示聚合和脱敏摘要。 |
| 供应商 | OCR、地图、天气、GPT、存储 | 健康、延迟、错误率、用量、熔断状态、密钥引用名。 |
| 配置 | 功能开关、默认分类、系统限额 | 灰度发布、上传大小、OCR 阈值、保留期限；每次修改记录版本。 |
| 安全审计 | 管理员、审计日志、登录事件 | 管理员状态、TOTP、会话、IP、所有高风险操作。 |

## 5. 关键页面设计

### 5.1 运行概览

这是一张工作台，不做营销式大屏。顶部只显示四个固定数字：

- 正在失败的任务数。
- 15 分钟 API 错误率。
- 等待发送和发送失败的提醒数。
- 对象存储与数据库用量。

下方按时间排列异常流：任务失败、供应商熔断、推送失败突增、删除任务卡住。每一行只提供一个主要命令，例如“查看错误”“重试任务”“暂停供应商”。

### 5.2 任务中心

任务字段：

| 字段 | 说明 |
| --- | --- |
| 类型 | ocr_meter、ocr_receipt、notify、export、import、report、ai_analysis。 |
| 状态 | queued、running、retrying、succeeded、failed、cancelled、dead_letter。 |
| 租户 | householdId；列表只显示缩略 ID。 |
| 关联资源 | meterId、transactionId、reminderId 或 exportId。 |
| 尝试次数 | 当前次数 / 最大次数。 |
| 错误分类 | transient、validation、provider、bug。 |
| requestId | 关联 API 与 Worker 日志。 |

重试只允许 transient 和 provider 类失败；validation 失败应回到用户确认页，不允许后台强行重试。进入 dead_letter 的任务必须有人工处理记录。

### 5.3 用户与家庭

列表默认只显示：

- 用户 ID、昵称、脱敏联系方式、账户状态、最后活跃时间。
- 家庭数量、设备数量、数据导出/删除状态。
- 最近 30 天任务失败数量。

用户详情的敏感字段默认遮罩。需要查看原始图片、精确地址或完整账务时，管理员提交“临时敏感访问”：

1. 填写用途、目标资源和 30 分钟以内有效期。
2. system_owner 审批；个人自用时仍要求再次 TOTP。
3. 系统写入访问令牌、审计记录和水印。
4. 到期自动收回，无法续期。

### 5.4 数据请求

数据导出与删除都必须是异步状态机：

~~~text
requested -> approved -> running -> completed
                    -> rejected
                    -> failed
~~~

删除申请在 running 前保留 7 天撤销期；执行后删除私有对象、业务数据和搜索索引，并保留不可逆的最小审计摘要。导出文件使用一次性下载地址，24 小时后自动清理。

### 5.5 供应商与配置

供应商页不显示完整密钥，只显示 secretRef、最后轮换时间、调用量、p50/p95 延迟、错误率、熔断状态。

### 5.6 AI建议

AI建议页看的是产品质量，不是用户账本后台。

- 省钱建议生成量、采用率、忽略率和稍后率。
- 建议类型分布：unnecessary_spending、recurring_bill、budget_risk、reminder_timing、charge_plan。
- 预计节省金额分布只展示区间，例如 0-50、50-200、200+，不展示用户完整消费明细。
- 失败原因：输入数据不足、模型超时、供应商限流、规则计算失败。
- 可关闭某类建议或调高阈值，例如“少于 ¥30/月的节省不提示”。

后台不能替用户采用建议；采用必须由用户端触发并写审计。

配置采用版本化 JSON：

| 配置 | 例子 | 生效策略 |
| --- | --- | --- |
| OCR 置信度阈值 | meter=0.90，receipt=0.85 | 新任务立即生效。 |
| 文件上限 | 图片 10 MB、账单文件 20 MB | API 校验立即生效。 |
| 功能开关 | bill_import、gpt_report | 按家庭或用户灰度。 |
| AI建议阈值 | min_saving=3000、max_per_day=1 | 新分析任务立即生效。 |
| 数据保留期 | 原图 365 天、导出 1 天 | 定时任务执行。 |
| 提醒限额 | 每设备每小时 3 条 | 队列发送前校验。 |

任何配置变更都记录旧值、新值、操作者、原因、审批信息和 requestId。

## 7. 后台数据模型

| 表 | 关键字段 |
| --- | --- |
| admin_users | id、email、role、totp_enabled_at、status、last_login_at。 |
| admin_sessions | admin_user_id、device、ip_hash、expires_at、revoked_at。 |
| audit_logs | actor_type、actor_id、action、resource_type、resource_id、before_hash、after_hash、request_id。 |
| jobs | queue、type、status、tenant_id、payload_ref、attempts、error_code、run_at。 |
| provider_health | provider、window_start、requests、errors、p50_ms、p95_ms、circuit_state。 |
| feature_flags | key、scope_type、scope_id、value、version、updated_by。 |
| ai_suggestions | type、status、estimated_saving_fen、confidence、evidence_summary、created_resource_id。 |
| privacy_requests | type、subject_user_id、status、reason、expires_at、approved_by。 |
| sensitive_access_grants | requester、target、purpose、expires_at、revoked_at。 |

任务 payload 不能直接保存完整原图地址、完整密钥或用户完整联系方式；保留资源 ID 和脱敏摘要即可。

## 8. 异步任务与告警

BullMQ 队列按业务隔离：

| 队列 | 并发建议 | 重试策略 |
| --- | --- | --- |
| ocr | 2 到 4 | 指数退避，最多 3 次。 |
| ai | 1 到 2 | 供应商限流时退避，最多 2 次；只处理摘要，不处理原图。 |
| notification | 10 | 按设备与用户限流，最多 3 次。 |
| export | 1 到 2 | 单任务最长 15 分钟，失败人工重试。 |
| cleanup | 1 | 幂等执行，每日低峰。 |

告警阈值：

- 5 分钟 API 5xx 超过 2%。
- OCR 或通知失败率连续 15 分钟超过 10%。
- AI 分析任务失败率连续 30 分钟超过 20%，或建议生成量异常飙升。
- 队列等待超过 10 分钟。
- 删除申请超过 24 小时未进入 running。
- 私有对象存储超过容量阈值或签名下载异常激增。

告警消息只携带 requestId、任务摘要和资源 ID，不包含票据内容、地址和金额明细。

## 9. Node 实现建议

建议使用 TypeScript 单仓库：

~~~text
apps/
  api/           用户 API 与 admin API 路由
  worker/        BullMQ 消费者与定时任务
  admin-web/     Vue 管理端
packages/
  domain/        金额、读数、规则、状态机
  db/            数据库访问与迁移
  contracts/     OpenAPI 生成类型、DTO、错误码
  auth/          用户端与后台端鉴权
~~~

Node 本身足够。OCR、GPT、导出等慢操作全部进入队列，API 只做校验、写库和投递任务；不要让 Fastify 请求线程等待模型或第三方接口返回。

## 10. 上线验收

- 后台与用户端无法互换 token。
- 管理员启用 TOTP 后才能拥有写权限。
- 任何重试、撤销、导出、删除、配置修改、敏感访问都有 audit_log。
- 默认用户列表和任务列表不泄露原图、精确地址、完整手机号或账单明细。
- 任务可重试、可追踪、可关联 requestId；死信任务不会悄悄丢失。
- 对象存储只能用短期签名 URL 访问，导出文件自动过期。
