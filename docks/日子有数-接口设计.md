# 日子有数 LifeTally：接口设计

版本：0.2  
适用端：H5、Capacitor App、后台管理系统、异步 Worker  
接口风格：JSON over HTTPS，REST 为主，异步任务通过 Job 查询

## 1. 服务边界

~~~text
用户端 H5 / Android / iOS
        |
        | /api/v1
        v
Node API (Fastify)
        |-- PostgreSQL：正式业务数据、审计数据
        |-- Redis / BullMQ：OCR、GPT、通知、导出任务
        |-- 私有对象存储：票据、表计、物品图片
        |-- OCR / GPT / 天气 / 地图：只由服务端代理调用

后台管理端
        |
        | /admin/v1
        v
Node Admin API（独立登录态、角色和审计）
~~~

微信、支付宝的个人消费记录不提供可直接读取的开放接口。首版只支持付款截图、收据图片、账单导出文件和手动录入。

## 2. 通用约定

### 2.1 地址、版本与时间

- 用户 API：https://api.example.com/api/v1
- 管理 API：https://api.example.com/admin/v1
- 时间：RFC 3339 UTC，例如 2026-08-02T12:30:00Z
- 展示时间：由客户端按用户 timezone 转换，默认 Asia/Shanghai
- ID：服务端生成 ULID 字符串，不使用连续自增 ID

### 2.2 数值与枚举

| 数据 | 接口字段 | 规则 |
| --- | --- | --- |
| 金额 | amountFen | 整数分。例如 32.50 元传 3250。 |
| 表计读数 | reading | 十进制字符串，例如 "2818.2"。 |
| 用量 | usage | 十进制字符串，例如 "3.6"。 |
| 距离 | distanceMeters | 整数米。 |
| 时长 | durationSeconds | 整数秒。 |
| 分页 | cursor、limit | Cursor 分页；limit 默认 20，最大 100。 |

金额不允许客户端自行提交计算结果作为正式值。后端根据已确认读数、价格规则、充电记录或交易明细生成金额。

### 2.3 响应和错误

成功：

~~~json
{
  "data": {},
  "requestId": "01J4V9K7XCVQ6M9V0P8CN4B98S"
}
~~~

列表：

~~~json
{
  "data": [],
  "page": { "nextCursor": "01J4...", "hasMore": true },
  "requestId": "01J4..."
}
~~~

失败：

~~~json
{
  "error": {
    "code": "METER_READING_NOT_MONOTONIC",
    "message": "本次读数不能小于上次已确认读数",
    "details": { "previousReading": "2814.6" }
  },
  "requestId": "01J4..."
}
~~~

| HTTP | 典型错误码 | 客户端处理 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 标出字段，不关闭表单。 |
| 401 | UNAUTHENTICATED | 尝试刷新登录态；失败后回登录。 |
| 403 | FORBIDDEN | 提示无权限，不暴露资源是否存在。 |
| 404 | NOT_FOUND | 资源被删除或不存在。 |
| 409 | VERSION_CONFLICT | 拉取最新数据后提示用户重试。 |
| 422 | METER_READING_NOT_MONOTONIC、OCR_CONFIRM_REQUIRED | 保留确认页，要求修正或显式确认。 |
| 429 | RATE_LIMITED | 显示稍后再试。 |
| 500 | INTERNAL_ERROR | 显示请求编号，服务端记录上下文。 |

所有可重试写操作支持 Idempotency-Key 请求头；同一用户、同一路径、同一键在 24 小时内只执行一次。

## 3. 鉴权与会话

### 3.1 用户端

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /auth/code/request | 请求邮箱或手机号验证码。 |
| POST | /auth/session | 验证验证码，创建用户会话。 |
| POST | /auth/refresh | 刷新访问令牌。 |
| DELETE | /auth/session | 当前设备退出。 |
| GET | /me | 当前用户、家庭、时区和功能开关。 |
| PATCH | /me | 更新昵称、时区、偏好。 |
| POST | /devices | 登记设备与推送 token。 |

访问令牌使用 15 分钟 JWT。H5 的刷新令牌必须存入 Secure、HttpOnly、SameSite=Lax Cookie；原生 App 存入系统安全存储。禁止把第三方 API Key 下发给客户端。

### 3.2 后台端

后台使用独立的 /admin/v1/auth/*，不复用用户 JWT。登录要求密码和 TOTP；高风险操作再次校验 TOTP。后台令牌只允许从管理域名发起请求。

## 4. 核心用户接口

### 4.1 今日页与统计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /dashboard/today | 今日待办、预算、待确认 OCR、通勤与充电建议。 |
| GET | /reports/spending | 月度支出、分类占比、预算消耗。 |
| GET | /reports/energy | 电表用量、电费、充电费用趋势。 |
| GET | /reports/commutes | 距离、通勤时长、每公里成本。 |

GET /dashboard/today 返回的 actions 已按优先级排序，客户端只渲染前 3 项。行动卡必须携带 kind、targetId、cta 和 dueAt，不能让客户端猜测跳转逻辑。

### 4.2 文件上传与 OCR

上传采用三步，避免 API 进程中转大文件。

1. POST /uploads 创建上传意图，参数含 purpose、mimeType、sizeBytes、sha256。
2. 客户端按返回的 uploadUrl 直传私有对象存储。
3. POST /uploads/{uploadId}/complete 校验对象并返回 fileId。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /ocr/meter-reads | 以 fileId 创建表计 OCR 任务。 |
| POST | /ocr/receipts | 以 fileId 创建票据/付款截图 OCR 任务。 |
| GET | /jobs/{jobId} | 查询 queued、running、succeeded、failed。 |
| GET | /files/{fileId}/view-url | 获取 5 分钟有效的预览地址。 |

~~~json
POST /ocr/meter-reads
{
  "meterId": "01J4METER...",
  "fileId": "01J4FILE..."
}
~~~

OCR 成功结果只写入候选记录：

~~~json
{
  "data": {
    "candidateId": "01J4CAND...",
    "status": "pending_confirmation",
    "reading": "2818.2",
    "confidence": 0.98,
    "sourceFileId": "01J4FILE..."
  }
}
~~~

### 4.3 表计、价格规则和费用

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | /meters | 表计列表、创建电/水/燃气表。 |
| GET/PATCH | /meters/{meterId} | 表计配置与提醒。 |
| GET/POST | /meters/{meterId}/readings | 已确认读数列表、手动新增。 |
| POST | /meters/{meterId}/readings/confirm | 确认 OCR 候选或人工读数，并计算费用。 |
| GET/POST | /price-rules | 固定、阶梯、峰谷价格规则。 |
| POST | /price-rules/{ruleId}/validate | 用样例读数验证规则。 |

~~~json
POST /meters/{meterId}/readings/confirm
{
  "candidateId": "01J4CAND...",
  "reading": "2818.2",
  "recordedAt": "2026-08-02T12:00:00Z",
  "priceRuleId": "01J4RULE...",
  "expectedVersion": 7
}
~~~

服务端事务顺序：

~~~text
校验读数 >= 上次确认读数
  -> 计算用量
  -> 用规则计算金额与计算明细
  -> 写 confirmed meter_reading
  -> 写 energy_expense transaction
  -> 更新报表聚合与提醒
~~~

### 4.4 交易、预算和固定账单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | /transactions | 查询或创建交易。 |
| GET/PATCH/DELETE | /transactions/{transactionId} | 查看、修改、软删除。 |
| POST | /transactions/{transactionId}/confirm | 确认 OCR 或导入候选交易。 |
| POST | /transactions/imports | 创建账单导入任务。 |
| GET/PUT | /budgets/{month} | 总预算和分类预算。 |
| GET/POST | /recurring-bills | 固定账单。 |
| POST | /recurring-bills/{billId}/mark-paid | 标记本期已缴并生成交易。 |

~~~json
POST /transactions
{
  "direction": "expense",
  "amountFen": 3250,
  "occurredAt": "2026-08-02T00:12:00Z",
  "categoryId": "food",
  "source": "manual",
  "merchant": "早餐铺",
  "paymentMethod": "wechat_pay",
  "note": ""
}
~~~

交易状态：pending_confirmation、confirmed、voided。统计默认只读取 confirmed；报表可显式请求包含候选数据。

### 4.5 AI 省钱分析与提醒建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /ai/spending-insights | 获取省钱、预算风险和提醒优化建议。 |
| POST | /ai/spending-insights/generate | 手动触发一次 AI 分析任务。 |
| POST | /ai/suggestions/{suggestionId}/actions | adopt、dismiss、remind_later。 |

GET /ai/spending-insights 默认只返回当前月份的新建议。所有金额都由服务端规则预先算好，AI 解释不得覆盖 estimatedMonthlySavingFen。

~~~json
{
  "data": [
    {
      "id": "01J4TIP...",
      "kind": "unnecessary_spending",
      "title": "奶茶频率可以降一点",
      "summary": "本月 9 次共 ¥162，降到每周 1 次预计本月可省 ¥90。",
      "estimatedMonthlySavingFen": 9000,
      "estimatedYearlySavingFen": 108000,
      "confidence": 0.82,
      "evidence": [
        { "label": "本月奶茶", "value": "9 次 / ¥162" },
        { "label": "建议目标", "value": "每周 1 次" }
      ],
      "proposedAction": {
        "type": "create_saving_goal",
        "title": "奶茶每周最多 1 次",
        "targetMonthlyFen": 7200
      }
    }
  ]
}
~~~

~~~json
POST /ai/suggestions/{suggestionId}/actions
{
  "action": "adopt",
  "target": "create_reminder"
}
~~~

采用动作只允许生成受控资源：saving_goal、budget_rule、reminder_rule 或 checklist_rule。dismiss 会记录原因，用于后续降频；remind_later 只改变建议展示时间，不创建通知。

~~~json

{
  "status": "completed",
  "startedAt": "2026-08-02T13:00:00Z",
~~~

## 6. 事件、任务和一致性

写入正式数据后，服务端在同一数据库事务中写 outbox_events；Worker 再消费事件更新报表、排程提醒或调用第三方。这样即使外部服务超时，交易和读数也不会丢失。

| 事件 | 消费者 |
| --- | --- |
| meter_reading.confirmed | 费用交易、能源报表、异常检测。 |
| transaction.confirmed | 预算聚合、月报。 |
| transaction.confirmed | AI 省钱建议候选、异常分类检测。 |
| charge.completed | 续航状态、通勤成本、充电提醒。 |
| reminder.due | App Push、本地通知同步、审计。 |
| ai_suggestion.adopted | 创建 saving_goal、budget_rule、reminder_rule 或 checklist_rule。 |
| privacy.deletion_requested | 导出冻结、对象存储删除、账号去标识化。 |

## 7. 实现顺序

1. 鉴权、家庭隔离、审计基础、文件直传。
2. 交易、预算、固定账单、今日页。
3. 表计 OCR 候选、确认读数、价格规则和费用交易。
4. 电车、充电、提醒和通勤简报。
5. AI 省钱分析、建议采用动作和提醒优化。
6. 物品位置、导出删除、后台管理与供应商监控。

详细可导入接口见同目录 openapi.yaml。实现接口时，以 OpenAPI 和本文件的业务规则共同作为契约；字段有冲突时，以 OpenAPI 为准并同步更新本文档。
